# Claude 명령어: Verify

테스트 프레임워크가 없는 이 레포에서 변경을 검증합니다.

## 사용법

```
/verify
```

## 프로세스

1. `npm run lint` 실행
2. `npx next typegen` 실행
   - 건너뛰면 깨끗한 코드도 실패한다. 새 클론은 `LayoutProps`를 찾지 못하고(TS2304), 새 라우트는 옛 `.next/types`에 없어 TS2322가 난다.
3. `npx tsc --noEmit` 실행
   - `npm run build`는 쓰지 않는다. 타입만 확인하면 되는데 빌드는 느리고 `tsconfig.json`을 다시 쓸 수 있다.
   - `.next/dev/types/validator.ts`에서 함께 나는 TS2307(없는 `page.js`)과 TS2344(`__InvalidParamMatchingKeys`)는 지운 라우트의 생성 파일이 남은 것이다. 코드 오류와 구분해, dev 서버를 다시 띄우거나 `.next/dev/types`를 지운 뒤 다시 돌리라고 알린다.
4. tsc 오류를 **파일명 + 메시지**로 분류한다. 줄 번호는 편집에 따라 움직이므로 비교 기준으로 쓰지 않는다.
   - 기존 오류: 아래 선행 오류 목록과 일치하는 것
   - 새 오류: 그 밖의 모든 오류
5. 아래 보고 형식으로 출력한다.
6. 브라우저 확인은 하지 않는다. 화면이 바뀌는 변경이면 "수동 확인 필요"로 적는다.

## 선행 오류 (0건)

없음. 깨끗한 main에서도 나는 오류가 다시 생기면 파일명 + 메시지로 여기에 적는다.

## 보고 형식

```
lint: 통과 | 오류 N건 (목록)
tsc: 전체 N건 (기존 N건 / 새 오류 N건)
새 오류: (파일명 — 메시지, 없으면 "없음")
판정: 통과 | 실패
브라우저: 해당 없음 | 수동 확인 필요
```

- 판정은 lint 오류 0건 + tsc 새 오류 0건이면 통과다.
- 선행 오류가 사라졌으면 판정과 별개로 "선행 오류 목록 갱신 필요"라고 알린다.

## 참고사항

- 실패를 통과처럼 요약하지 않는다. 오류 출력은 원문 그대로 붙인다.
- 오류를 고치지 않는다. 이 커맨드는 보고만 한다.
